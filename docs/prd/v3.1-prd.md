## 1. Background

v3.0 finds secrets in agent memory but is **read-only**: users must delete leaked lines by hand, and Claude Code
transcripts are large JSONL files that are painful to edit. Testing v3.0 against OpenClaw 2026.6.35 also surfaced:

- `openclaw config set <path> <token>` writes argv (token included) to `~/.openclaw/logs/config-audit.jsonl`.
  Telegram `botToken` is masked there, but `channels.discord.token` and `gateway.auth.token` are not.
- OpenClaw's rotating `openclaw.json.bak`, `.bak.1`, … keep plaintext tokens after migration.
- `openclaw secrets audit` reported `gateway.auth.token` but not a plaintext `channels.discord.token`.
- `~/.openclaw/agents/main/sessions` is created with mode `755`.

The research behind v3.0 (ClawHavoc malicious skills, Snyk ToxicSkills, memory-poisoning papers such as
arXiv 2604.16548 / 2606.24322 / 2608.21230, OWASP Agentic Top 10, Unicode-tag injection in skills) motivates
the "red-teaming" features that were intentionally deferred from v3.0.

## 2. Goals / non-goals

**Goals**
1. Close the loop: find → **redact** → rotate → prevent.
2. Cover the remaining places tokens live on a Claude Code machine (config, MCP env, shell history).
3. Add advisory red-team checks: memory poisoning, malicious skills, exposed gateway.

**Non-goals**
- No network calls, no cloud service, no dependency beyond the Python standard library.
- No automatic credential rotation at providers (we link to the rotation page).
- No claims of "safe": red-team checks are heuristics and must say "review", never "clean".

## 3. Features

### P0-1 `redact` — in-place redaction of memory, transcripts and logs

**User story:** "Scan found my OpenAI key in MEMORY.md and three transcripts — remove it everywhere."

Requirements
- `redact --dry-run` (default when run by the agent first) and `redact --apply`, driven by the `memory` scan
  output: `--fingerprints sha256:… [...]` or `--all`. Values are re-detected from disk, never passed in.
- Replacement token: `[REDACTED:<detector>:<fingerprint>]` (keeps the place readable and correlatable).
- Text / Markdown: line-preserving replace. JSONL: replace inside each line and assert every line still
  `json.loads`; abort the file if not. Keep file mode, write atomically.
- SQLite: **report-only** in v3.1 (print the exact `openclaw` command or explain the session must be deleted).
- Backups: `<file>.tsc-bak-<timestamp>` with `chmod 600`, plus a manifest `~/.local/state/token-safety-checker/redact-<ts>.json`
  (paths + fingerprints, never values). `redact --restore <manifest>` restores.
- `--clean-backups` removes redaction backups after the user confirms rotation.
- Warn when target is an active Claude Code session transcript (mtime < 2 min): suggest closing the session first.
- Output says explicitly: "Redaction does not un-send the secret — rotate it."

Acceptance criteria
- Tests: md, jsonl (incl. secret inside escaped JSON string), multiple secrets per line, live-match secret,
  restore round-trip byte-identical, no secret value in any stdout/stderr (existing `assert_no_secrets` helper).
- E2E: `claude --resume` still opens a redacted transcript (manual check, documented in PR).
- SKILL.md workflow B updated: scan → show → confirm → `redact --dry-run` → confirm → `redact --apply` → rotate.

### P0-2 Claude Code config secrets

Scan with the same detectors + key heuristics:
- `~/.claude.json` → `mcpServers.*.env`, `mcpServers.*.headers`, project-scoped `projects.*.mcpServers`
- `~/.claude/settings.json`, `.claude/settings.json`, `.claude/settings.local.json` → `env`
- `.mcp.json` (committed!) → literal keys in `env` / `headers` / `args`

Fix path (`migrate --claude`): replace literal values with `${VAR}` expansion and append exports to the profile
(reuse v3.0 profile logic). Refuse on `.mcp.json` files tracked by git unless `--force`, and warn that git history
still has the value (reuse `--deep` logic for any file path).

Acceptance: fixtures for each file; `claude mcp list` still shows the servers after migration (integration test,
skipped without `claude`).

### P1-1 Memory poisoning heuristics (advisory, "red-team")

Flag in memory files / CLAUDE.md / rules (not transcripts by default):
- invisible Unicode: tag block U+E0000–E007F, zero-width (U+200B–200D, U+2060, U+FEFF), bidi overrides (U+202A–202E, U+2066–2069)
- instruction-like text aimed at the agent: "ignore (all|previous) instructions", "you must always", "do not tell the user", "system prompt"
- exfil patterns: `curl|wget|fetch` to non-allowlisted hosts with query data, `| sh`, `| bash`, markdown images with query strings
- large base64 blobs (> 200 chars) and data URIs
Output: `poisoning[]` with file, line, rule id, short **sanitized** excerpt (invisible chars rendered as `<U+E0041>`).
Severity is always "review". `--allow-host` list in a config file.

Acceptance: fixtures per rule, false-positive check against a corpus of ordinary CLAUDE.md files (aim < 1 flag per 50 files).

### P1-2 Installed skill supply-chain audit

`audit-skills` over `~/.openclaw/skills`, `~/.openclaw/workspace/skills`, `~/.claude/skills`,
`~/.claude/plugins/cache/**/skills`, project `.claude/skills`:
- ClawHavoc patterns: "prerequisite" installers, `curl … | bash`, password-protected archives, downloads of executables
- reads of credential paths: `~/.openclaw/credentials`, `openclaw.json`, `.env`, `~/.ssh`, `~/.aws`, browser profiles, keychains
- hidden content in SKILL.md: HTML comments, invisible Unicode (reuse P1-1)
- declared vs actual: compare `metadata.openclaw.requires` with binaries invoked in scripts
Output per skill: risk + reasons; link to `clawhub scan --slug` when the skill came from ClawHub.

### P1-3 Gateway exposure check (OpenClaw)

Read-only checks on `openclaw.json`: `gateway.bind` not loopback, `gateway.auth.mode` = `none`, tunnel config
without auth, `controlUi` exposed. If `openclaw` CLI is present, run `openclaw security audit --json` and merge its
findings (do not duplicate). Permission checks: `~/.openclaw` 700, `credentials/` 700/600,
`agents/*/sessions` 700 (seen as 755 in testing).
